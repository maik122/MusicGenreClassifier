# 🎵 Genre.AI — Music Genre Classifier

A machine learning project that classifies music into 10 genres using audio feature extraction and a Random Forest classifier. Built on the GTZAN dataset with a Streamlit demo app.

**[Live Demo →]()** <!-- update after deploy -->

---

## Results

| Model | Accuracy | Notes |
|-------|----------|-------|
| Random Forest (tabular features) | **77%** | 200 trees, 58 audio features |
| CNN — ResNet50 (spectrograms) | ~20% | Limited by dataset size (~80 images/genre) |

### Per-Genre Performance (Random Forest)

| Genre | Precision | Recall | F1 |
|-------|-----------|--------|----|
| Classical | 1.00 | 1.00 | 1.00 |
| Metal | 0.86 | 0.96 | 0.91 |
| Jazz | 0.91 | 0.95 | 0.93 |
| Blues | 0.65 | 0.85 | 0.74 |
| Rock | 0.61 | 0.52 | 0.56 |

Classical and metal are the easiest to classify — they have distinct acoustic signatures. Rock and blues overlap heavily in tempo, spectral content, and instrumentation, making them the hardest to separate.

## Quickstart

### 1. Clone the repo

```bash
git clone https://github.com/maik122/MusicGenreClassifier.git
cd music-genre-classifier
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

> **M1/M2/M3 Mac users** — replace `tensorflow` with:
> ```bash
> pip install tensorflow-macos tensorflow-metal
> ```

### 3. Download the dataset

Download the [GTZAN dataset from Kaggle](https://www.kaggle.com/datasets/andradaolteanu/gtzan-dataset-music-genre-classification) and place it in `Data/` so the structure matches above.

### 4. Train the models

Open and run all cells in `notebooks/train.ipynb`. This saves the trained models to `models/`.

```bash
cd notebooks
jupyter notebook train.ipynb
```

### 5. Run the app

```bash
streamlit run app.py
```

## How It Works

### Feature Extraction

Each audio track is analysed with `librosa` to extract 58 features:

| Feature | Description |
|---------|-------------|
| MFCCs (1–20) | Mel-frequency cepstral coefficients — capture timbre |
| Chroma STFT | Pitch class energy — captures harmony |
| Spectral Centroid | Brightness of sound |
| Spectral Bandwidth | Width of the frequency range |
| Spectral Rolloff | Frequency below which 85% of energy falls |
| Zero Crossing Rate | How often the signal crosses zero — proxy for noisiness |
| RMS Energy | Loudness |
| Tempo | BPM estimated via beat tracking |
| Harmony / Perceptr | Harmonic and percussive components |

### Model

A **Random Forest** with 200 trees is trained on these 58 features. The features are standardised with `StandardScaler` before training.

```
Input audio → librosa feature extraction → StandardScaler → Random Forest → Genre + probabilities
```

### Why Random Forest outperforms CNN here

The CNN (ResNet50) only reaches ~20% accuracy because the spectrogram image dataset has ~80 images per genre — far too few for deep learning. The tabular features capture enough acoustic information that a well-tuned Random Forest generalises effectively at this data scale.

## Dataset

**GTZAN Genre Collection** — 1,000 audio tracks, 30 seconds each, across 10 genres (100 tracks per genre). Widely used benchmark for music genre recognition.

> Tzanetakis, G. and Cook, P. (2002). Musical Genre Classification of Audio Signals. *IEEE Transactions on Speech and Audio Processing*.
